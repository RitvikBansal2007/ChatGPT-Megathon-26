# GreenDash

Setup and run instructions. The solution is described in `deliverables/final_report.pdf` and `Code/docs/SOLUTION.md`.

## Requirements

- Python 3.11 or newer (the code also runs on 3.10)
- macOS, Linux or Windows. `make` is optional: every command below has a plain-Python form,
  and `python scripts/demo.py` starts the demo on Windows without WSL or `make`.

## Setup

```bash
cd Code
python -m venv .venv
source .venv/bin/activate          # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -e . pytest httpx streamlit plotly
```

## Build everything

Runs data generation, feature building, model training and calibration, evidence packs, evaluation and the run manifest. About 3 minutes; fixed seed; two runs produce the same manifest hash.

```bash
make pipeline
```

Without `make`:

```bash
python -m greendash.generator && python -m greendash.features
python -m greendash.categoriser.evaluate && python -m greendash.models.train
python -m greendash.models.calibrate && python -m greendash.models.generate_hashes
python -m greendash.packs && python -m greendash.cache
python -m greendash.models.score && python -m greendash.models.evaluate_models && python -m eval.report
python -m greendash.manifest
```

## Run the application

Starts the API on `127.0.0.1:8000` and the web app on <http://127.0.0.1:8501>. Secrets for the run are generated on the fly and never written to disk.

```bash
make demo                  # or, on any platform:  python scripts/demo.py
```

It checks the packs exist and the ports are free, waits for the API to be healthy, and stops
both processes on Ctrl+C. In the sidebar choose a role (Evaluator sees everything) and a customer.

The app also runs without the API, on bundled sample data (no pipeline needed):

```bash
make demo-offline          # or:  python scripts/demo.py --no-live
```

## Language model (optional)

Without a key, every explanation uses checked fixed wording. To have explanations written by the model:

```bash
cp .env.example .env      # then set GEMINI_API_KEY in .env (the file is git-ignored)
make warm                 # pre-generates explanations for the 8 demo customers
```

## Tests

```bash
make test                  # or:  python -m pytest -q app/tests tests/
```

The first run builds the synthetic data the scenario and invariance tests read (about 20 seconds); later runs reuse it.

## Datasets and model weights

- **Synthetic banking data:** generated by `make pipeline` (`python -m greendash.generator`), seed 42. No real customer data is used.
- **London smart-meter electricity data (Low Carbon London, UK Power Networks):** <https://data.london.gov.uk/dataset/smartmeter-energy-use-data-in-london-households>. Only an aggregate profile derived from it is in the repository (`Code/data/priors/lcl_profile.json`). To rebuild it, download `CC_LCL-FullData.csv` into `Code/dataset/` and run `make lcl`.
- **Emission factors:** UK Government GHG conversion factors (DESNZ, 2024), in `Code/config/factors.csv`.
- **Model weights:** the four trained models are in `Code/data/models/` and are rebuilt by `make pipeline`. Nothing is hosted externally.

## Other commands

| Command | What it does |
|---|---|
| `make data` / `features` / `train` / `packs` / `eval` | Individual pipeline steps |
| `python -m eval.llm_eval.judge` | Explanation evaluation (needs `GEMINI_API_KEY`) |
| `make audit` | Static security checks (needs `bandit`, `pip-audit`, `gitleaks`) |
