# GreenProof Backend API Contracts

This document outlines the expected request/response schemas and error-handling conventions for the GreenProof backend services (Scoring, Carbon Engine, and LLM Explainer). It is designed to help align the Claim-Check gateway and orchestrator integration.

---

## 1. LLM Explainer API
**Purpose:** Generates a faithful, user-friendly explanation of why a green product was recommended.

**Expected Request Payload (`evidence_pack`):**
```json
{
  "customer_id": "string",
  "recommendation": "string",  // e.g., "GP01", "GP02"
  "confidence": 0.85,          // float
  "reasons": [
    {
      "code": "string",        // e.g., "HIGH_FUEL_SPEND", "LOW_DIGITAL_ADOPTION"
      "value": 250.0           // float
    }
  ]
}
```

**Expected Response Payload:**
```json
{
  "explanation": "string",     // The natural language explanation generated by the LLM
  "metrics_summary": "string"  // A summary of the carbon/financial metrics
}
```

**Error Handling Conventions:**
*   **Budget Exceeded (`HTTP 429` / `503`):** The LLM explainer has a `CostTracker` that throws an exception if the budget limit is exceeded (`BUDGET EXCEEDED: Total LLM cost...`). The gateway must intercept this and return a standard fallback response.
*   **LLM Hallucination/Format Failure (`HTTP 500`):** If the LLM returns invalid JSON, the service gracefully degrades and returns: `{"explanation": "Failed to generate explanation.", "metrics_summary": ""}`. The gateway can pass this through or substitute a standard UI error state.

## 2. Carbon Engine API
**Purpose:** Deterministically calculates estimated carbon, energy, or paper savings for a recommended product.

**Expected Request Payload:**
```json
{
  "product_id": "string",      // e.g., "GP01"
  "features": {
    "has_car": true,
    "annual_mileage": 12000,
    "fuel_type": "petrol",
    "home_owner": true,
    "gas_kwh": 11500,
    "roof_suitability": "suitable",
    "existing_solar": false,
    "accessibility_paper_need": false,
    "paper_statements_12m": 12
  }
}
```

**Expected Response Payload:**
```json
{
  "status": "string",          // "ESTIMATED", "INSUFFICIENT_DATA", or "NOT_APPLICABLE"
  "low": 0.0,                  // float
  "central": 0.0,              // float
  "high": 0.0,                 // float
  "formula": "string",         // The formula string used for the calculation
  "missing_inputs": ["string"],// List of missing feature keys if status == INSUFFICIENT_DATA (Optional)
  "display": {                 // Formatted strings for UI rendering (Optional)
    "central": "string",
    "range": "string"
  }
}
```

**Error Handling Conventions:**
*   **Missing Features (`HTTP 400`):** If required fields are missing for a specific product, the engine returns `status: "INSUFFICIENT_DATA"` with the `missing_inputs` list populated. It does *not* throw an exception. The gateway should handle this gracefully (e.g., prompting the user for more info).
*   **Ineligible Customer (`HTTP 400`):** If a customer does not possess the requisite asset (e.g., recommending EV switch to someone without a car), the engine returns `status: "NOT_APPLICABLE"`.

## 3. Recommendation Scoring API
**Purpose:** Predicts customer propensity for all green products and selects the top recommendation.

**Expected Request Payload:**
```json
{
  "customer_ids": ["string"]   // List of customer IDs
}
```

**Expected Response Payload:**
```json
[
  {
    "customer_id": "string",
    "RECOMMEND": "string",           // The top recommended product (e.g., "GP01")
    "RECOMMEND_SCORE": 0.0,          // float (calibrated probability for the top product)
    "score_take_up_GP01": 0.0,       // float
    "score_take_up_GP02": 0.0,       // float
    "score_take_up_GP03": 0.0,       // float
    "score_take_up_GP04": 0.0        // float
  }
]
```

**Error Handling Conventions:**
*   **Security/Hash Mismatch (`HTTP 500`):** The scoring service verifies the SHA256 hashes of the model weights before loading. If they are compromised, it raises `Exception("Security Error: Hash mismatch...")`. The gateway must immediately abort the transaction.
*   **Missing Customer (`HTTP 404`):** If the `customer_id` is not found in the feature store, the backend returns empty results or `None`.
